# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **PCDT heading keywords**: `scripts/build_pcdt_keywords.py` derives per-protocol keywords from each PCDT's numbered section headings into `data/govbr_pcdt_keywords.json` (generic process, document-part and English words and split-word fragments are dropped; words shorter than 4 letters survive only as acronyms standing alone in a heading, such as HIV or DIP); `load_seed_catalog` merges them so the catalog search finds umbrella protocols by the conditions they cover. A keyword-only match scores 0.7x of the same match on title, slug or description, so it ranks below an equally strong title match. `GovBrPCDTEngine.search` drops the word "pcdt" from queries that carry other words (every row is a PCDT; the token only diluted the score of rows without it). On `search_guidelines(collection="all")` the keywords travel on `BrazilGuideline.keywords`: the BVS-outage topic gate reads them and ignores "pcdt" beside other words (it emptied the pool before), and `rank_brazil_guidelines` scores them with the abstract, at half the title weight. With BVS down, "sifilis PCDT" returns the IST protocol and "chagas PCDT" the Chagas protocol; with BVS answering "sífilis"-titled manuals, the IST protocol stays inside the default limit. Cache schemas bumped to v4 so cached rankings do not mask the change. Cached rankings key on CACHE_SCHEMA only, so a regenerated keyword file needs a schema bump to take effect before the cache TTL ends.
- **`search_clinical_trials` MCP tool**: exposes `ClinicalTrialsClient.search_clinical_trials` with its optional `intervention` and `condition` arguments (`limit` clamped to 1-50). Before, no tool reached the client directly, and `search_medical_databases` sends the query alone.
- **OA-annotation skip logging**: when the batched Europe PMC OA-status lookup fails (EBI outage, non-200, or malformed payload), `annotate_oa_status` logs one INFO line per failed request (a `search_papers` page is one request) naming how many papers keep `oa_status="unknown"`, so missing OA fields in `search_papers` results are attributable to the outage. Previously the skip was silent at the provider layer; the http-layer WARNING was the only trace. If the failure occurs mid-annotation (malformed row in an otherwise valid payload), the count names only the papers that were not yet annotated — counted once each, even when Europe PMC returns the same identifier in more than one row — and nothing is logged when every paper in the request was already annotated.
- **`BvsGuard` (`medical/bvs_guard.py`)**: process-wide single-flight for identical BVS requests, a cap on requests in flight (`BRAZIL_MAX_CONCURRENT`, 2) and a breaker (`BRAZIL_BREAKER_THRESHOLD` 2 consecutive timeouts/5xx, `BRAZIL_BREAKER_COOLDOWN_S` 60) that makes searches skip BVS and answer from the gov.br catalogs. Concurrent callers no longer each pay a full stage budget against the same sick host.
- **`OPENALEX_API_KEY` setting**: passed as `api_key` on every OpenAlex request (`OpenAlexProvider._params`). Keyless requests share OpenAlex's per-IP daily budget (1000 credits); a free key gets its own (10000). Redacted from logs like the other credential params.
- **`retryable_statuses` parameter on `AsyncHttpClient.get()`**: callers can override the default `RETRYABLE_STATUS_CODES` per request; Europe PMC `fullTextXML` uses it to fail fast on the 500 that means "no OA XML" instead of making four attempts (PR #39).
- **gov.br "Saúde de A a Z" publication scraper (`GovBrAZEngine`)**: Indexing `/centrais-de-conteudo/publicacoes/svsa/<topic>` and `/centrais-de-conteudo/publicacoes/guias-e-manuais/<year>`, including the Dengue clinical management and Tuberculosis control manuals.
- **`collection="az"` for `brazil_guidelines` tool**: New collection option in `search_brazil_moh_guidelines`; records also appear in the default `collection="all"` results and full text resolves via `get_brazil_moh_full_text`.
- **`scripts/update_govbr_az_catalog.py`**: CLI script to regenerate the bundled `govbr_az_catalog.json` seed catalog.
- **Brazilian MoH guidelines tools**: `search_brazil_moh_guidelines` and `get_brazil_moh_full_text` MCP tools for Brazilian Ministry of Health technical publications (PCDT, CONITEC, cadernos, manuais) via BVS/iAHx API with allowlisted PDF full-text extraction, Portuguese language support, and exact-id deduplication (PR #19).
- **`CACHE_TTL_BRAZIL_MOH` setting**: Configurable cache TTL (default 2,592,000s / 30d) for caching Brazilian MoH searches and document full text in SQLite (PR #19).
- **`fonttools>=4.40.0` dependency**: Added to `pyproject.toml` for `pypdf` optional font processing support (PR #18).
- **HTTP diagnostic logging with credential redaction**: `AsyncHttpClient` logs `>= 400` errors, retries, timeouts, and exceptions with automatic query-parameter credential redaction (`api_key`, `apikey`, `email`, `token`, `access_token`) (PR #18).
- **Camoufox browser fallback for the mirror tier**: Last-resort headless anti-detection browser fallback in `MirrorProvider` for Cloudflare-protected/blocked mirrors, capped to 3 mirrors and 20s total timeout with `%PDF-` magic header validation (PR #17).
- **Direct PDF links in WHO IRIS**: `WHOGuideline.pdf_url` field exposed in WHO IRIS search results and markdown formatted responses (PR #16).
- **`get_who_iris_full_text` MCP tool**: Full-text retrieval for WHO IRIS guidelines from DSpace 7 PDF bitstreams with abstract fallback and serve-time character truncation (PR #14).
- **`search_who_iris_guidelines` MCP tool**: WHO IRIS guideline search in `prefix` (browse) and `fulltext` (search) modes, backed by `WHOIRISEngine` and `WHOGuideline` model (PR #13).
- **`CACHE_TTL_WHO_IRIS` setting**: Configurable cache TTL (default 2,592,000s / 30d) for caching WHO IRIS search results and full text in SQLite (PR #13).
- **Query-aware re-ranking** in `search_papers`: The relevance signal now blends real lexical coverage of the query against title (weighted 2x) and abstract with the source `1/sqrt(rank + 1)` position prior; previously the query was not used for scoring. New `ScoringEngine` primitives: `tokenize`, `text_coverage`, `best_matching_sentence`. `medical/ranking.py` refactored to reuse them (behavior preserved) (PR #10).
- **Evidence grade ranking signal**: `classify_evidence_grade` maps PubMed `PublicationType` to an Oxford CEBM-style ladder (`1a` / `1b` / `2b` / `3b` / `4` / `5`); the best (lowest-rank) grade wins when a paper carries multiple types. PubMed enrichment now captures `study_type` and `issn` to support it (PR #10).
- **Journal impact ranking signal**: `lookup_journal_impact(issn, venue)` resolves a Scimago SJR value with ISSN-first, normalized-name-second lookup. `src/scholar_mcp/data/scimago_sjr.json` ships empty; the signal contributes a neutral `0.0` for every paper until the dataset is populated (procedure: `src/scholar_mcp/data/SOURCES.md`). Regenerator: `scripts/update_scimago_data.py` (PR #10).
- **Author authority ranking signal**: Last-author h-index is fetched via OpenAlex batch (`fetch_work_details_batch`, `fetch_author_h_indices_batch`) and stored on `PaperMetadata.last_author_h_index` (PR #10).
- **`check_citations` MCP tool**: Verifies each `{"text", "identifier"}` claim against the cited paper's title/abstract (or full text with `deep=True`). Verdicts: `SUPPORTED` / `WEAK` / `UNSUPPORTED` / `NOT_FOUND`. Max 25 claims per batch; per-claim failures are isolated (PR #10).
- New `Settings` fields and environment variables: `ranking_weight_evidence_grade` (0.20), `ranking_weight_journal_impact` (0.10), `ranking_weight_author_authority` (0.05), `ranking_position_weight` (0.25), `ranking_recency_half_life_years` (7.0), `ranking_candidate_multiplier` (3), `ranking_min_candidates` (20), `ranking_max_candidates` (50), `ranking_enrichment_timeout` (1.5), `citation_check_supported_threshold` (0.5), `citation_check_weak_threshold` (0.15).
- New `PaperMetadata` fields: `issn`, `study_type`, `evidence_grade`, `last_author_h_index`.

### Changed

- **BVS browser fallback runs at most two browsers, shared by search and full-text lookups (PR #64)**: `_camoufox_fetch` takes one of `_CAMOUFOX_MAX_CONCURRENT` (2) per-engine slots, so the search chain's last-resort browser tier can now queue behind shielded full-text lookups; the wait spends its own chain ceiling. A caller whose wait leaves less than `_CAMOUFOX_MIN_USEFUL_CEILING_S` (20 s) skips the launch.
- **Mirror tier renamed; no mirror list ships with the package (breaking)**: the full-text tier between arXiv and the abstract fallback is `MirrorProvider` (`providers/mirrors.py`), and its `FetchAttempt.tier` and `FullTextResponse.source` label is `"mirror"`. Its settings are `ENABLE_MIRROR_TIER`, `PREFER_MIRRORS_OVER_UNPAYWALL`, `FULLTEXT_MIRRORS`, `MIRROR_TIMEOUT_S` and `MIRROR_TIER_TIMEOUT_S`; the earlier names are no longer read. The tier is skipped (`FULLTEXT_MIRRORS has no http(s) URL`) until `FULLTEXT_MIRRORS` names at least one base URL, and `PREFER_MIRRORS_OVER_UNPAYWALL` skips Unpaywall only while the tier can run. A `FULLTEXT_MIRRORS` entry that is not an `http(s)` URL with a host is dropped with a warning: a bare host failed every request yet still counted as configured.
- **Install from GitHub**: the Quick Start runs `uvx --from git+https://github.com/gustavokch/scholar-mcp scholar-mcp`. The `scholar-mcp` name on PyPI belongs to an unrelated project, so a bare `uvx scholar-mcp` started a different server.
- **Brazilian MoH search is at most three BVS requests, not seven**: strict title AND (first 4 tokens), title OR (all tokens), all-field OR. The right-to-left title-token relaxation ladder (`_title_token_relaxations`), the all-field AND stage and the separate `relaxed` stage are gone. A 6-9 term title AND never matched a formal title and each failed rung cost a full request against a host that takes tens of seconds.
- **`BRAZIL_STAGE_TIMEOUT_S` 30 → 45 and new `BRAZIL_REQUEST_TIMEOUT_S` (45)**: a degraded BVS host answers successfully only after 37-43 s (measured 2026-10-01), so the 30 s stage budget and the 30 s global per-attempt read timeout cancelled answers about to arrive. `AsyncHttpClient.get` gained `request_timeout` to override the per-attempt ceiling for one call; only BVS search passes it.
- **`BRAZIL_BROWSER_TIMEOUT_S` 45 → 150 and `BRAZIL_CHAIN_TIMEOUT_S` 120 → 300**: a camoufox launch plus page creation took 30-70 s on a loaded machine and the Bunny challenge needs about 12 s more, so the 45 s browser ceiling ended the tier before any payload arrived. The chain default keeps two full-ceiling stages (2 x 45 s) plus the full browser ceiling inside the bound. `_CAMOUFOX_NAV_TIMEOUT_MS` rises 90 s → 300 s so the navigation cap still sits above the browser ceiling. The adaptive over-fetch shrink now measures the chain minus the browser ceiling when the browser tier is enabled (150 s, so the window shrinks after 75 s). Against the whole 300 s chain the 150 s threshold sat past what three 45 s HTTP stages can reach, so the shrink never fired.
- **BVS browser fallback runs only for a CDN shield**: a timeout or 5xx comes from the origin, which Camoufox would reach just the same, so it only burned 20-45 s of chain budget.
- **WHO IRIS search takes PDF links from the list response**: `search_guidelines` sends `embed=bundles/bitstreams`, so DSpace returns each result's bundles and bitstreams with the page instead of the engine making two follow-up requests per result. Live (`malaria` title prefix, same `pdf_url` coverage): `limit=10` went from 21 requests / 5.0 s to 1 / 1.6 s, `limit=50` from 98 / 20.5 s to 5 / 5.7 s. The server's embed cost grows with page size (a 100-item page took 33-55 s against the 30 s `request_timeout`), so list pages are capped at `MAX_EMBED_PAGE_SIZE` (10) and a larger `limit` is split into equal pages. An item whose embed is partial or missing is still resolved with a request; a complete embed that shows no ORIGINAL PDF is final.
- **Journal-impact signal is live**: `scimago_sjr.json` now ships the SCImago Journal Rank 2025 table (52,793 ISSNs). It shipped empty before, so the 0.10 `journal_impact` weight contributed nothing. The data is SCImago's, for non-commercial use with citation (see `src/scholar_mcp/data/SOURCES.md`).
- **gov.br catalogs are offline-seed only**: `GovBrPCDTEngine` and `GovBrAZEngine` serve the bundled seed and never crawl gov.br or copy the seed into SQLite on a search. A missing seed reports `backend_error`.
- **`scripts/update_govbr_catalogs.py --catalog az|pcdt`** replaces `scripts/update_govbr_az_catalog.py` and refuses to write a partial crawl (any failed page, page-cap truncation, missing alias vocabulary, or a catalog below half the current size).
- **`RETRYABLE_STATUS_CODES` is now a `frozenset`**: the shared retry-status default can no longer be mutated in place by an importer (PR #39).
- **PMC OAI-PMH base URL**: `OAI_PMH_URL` now points at the canonical `https://pmc.ncbi.nlm.nih.gov/api/oai/v1/mh/`, removing a 301 redirect from every OAI request (PR #39).
- **Expected-error logging for Europe PMC and PMC OAI**: `fullTextXML` 404/500 and OAI `cannotDisseminateFormat` 400 now log at DEBUG instead of WARNING (PR #39).
- **Quieted routine HTTP retries**: Demoted 429/503 retry logs in `AsyncHttpClient` to `INFO`; `WARNING` is reserved for exhausted attempts (PR #18).
- **Bounded error body decode**: Sliced error response content to first 500 bytes and decoded with `errors="replace"` to prevent large/binary payload memory waste (PR #18).
- **Re-balanced default ranking weights**: `relevance` 0.30, `citations` 0.20, `recency` 0.15 (previously 0.4 / 0.3 / 0.3). The remaining 0.35 weight is split across the three new signals (0.20 + 0.10 + 0.05). Sum of the six signal weights is 1.0 (PR #10).

### Removed

- **`.github/workflows/publish.yml`**: it published to a PyPI project this repository does not own, so a release tag could only fail.

### Fixed

- **Shielded BVS full-text lookups retry through the browser (PR #64)**: `_lookup_record` stopped at `cdn_challenge` when BVS answered the `id:"..."` query with a Bunny 403 or shield HTML. It now retries once through `_camoufox_fetch` inside the `BRAZIL_FULLTEXT_TIMEOUT_S` deadline. An exact-id match is served, and a valid empty payload is `not_found`. A failed or malformed browser run, or one cut short by the ceiling, keeps `cdn_challenge`. A lookup the ceiling cuts short reports `timeout=True` whichever timer ends the browser. `_camoufox_fetch` returns `None` for a failed tier and `[]` for a valid empty payload. `_parse_docs` is now the only reader of the BVS envelope, so `_extract_docs` no longer raises on a non-dict `response`.
- **Bundled Brazil corpus holds only official texts**: two of the six local guideline files were 3 KB summaries written for the corpus ("Licença: Resumo técnico autoral") and served as Ministry of Health sources. `indicadores_aps_cofinanciamento_2025.txt` described the old prenatal indicator (six visits, the first by week 12) and never mentioned testing; it is replaced by the official Nota Metodológica C3 - Cuidado na Gestação e Puerpério (record `ms-nota-metodologica-c3-gestacao-puerperio-2025`). `vigilancia_enchentes_rs_2025.txt` is replaced by the 2017 Ministry of Health "Guia de preparação e resposta à emergência em saúde pública por inundação" (record `ms-guia-resposta-inundacao-2017`). The old record ids are gone. `brazil_moh.CACHE_SCHEMA` is now v6 and `govbr_common.CACHE_SCHEMA` v5: cached search, record and PCDT search rows still served the summaries for up to 30 days. A test fails if a catalog row or bundled file declares itself self-written.
- **Project links point at this repository**: `pyproject.toml` `Homepage`/`Repository` and the `SECURITY.md` private-reporting link named repositories that do not host this project; `SECURITY.md` now lists 1.x as the supported line.
- **`search_guidelines` keeps strong PCDT hits and sends BVS no document-type word**: the merge scored a protocol found only through its heading keywords at ~0.45 against 0.65-0.77 for BVS rows with a lexical match, so "sifilis" and "sifilis PCDT" cut the IST protocol (`pcdt-atencao-integral-as-pessoas-com-infeccoes-sexualmente-transmissiveis`, engine score 0.63) from the default six whenever four or more BVS rows matched. A `GovBrPCDTEngine` hit scoring at least `PCDT_FLOOR_SCORE` (0.5) is now pinned: it replaces the lowest-ranked unpinned row when ranking would cut it, and the result never exceeds `limit`. The pinned ids travel in the cached search row. The word "pcdt" is also dropped, by one shared helper (`govbr_common.strip_pcdt_token`, now used by `GovBrPCDTEngine.search` and the topic gate too), from every BVS composition, the ranking terms and the cache key: its OR and all-field forms matched unrelated CONITEC reports that mention a PCDT ("Methotrexate for the treatment of non-infectious uveitis" for "sifilis PCDT"), and "sifilis" and "sifilis PCDT" now share one cached row. `brazil_moh.CACHE_SCHEMA` is v5.
- **`get_drug_by_ndc` returns only the label that holds the NDC**: after a quoted miss it sent `openfda.product_ndc:{ndc}` unquoted, which openFDA splits on the hyphen, so `0591-2412` matched any labeler's `…-2412` and the first hit was returned and cached. The input is now normalised (two hyphens → `package_ndc`, one → `product_ndc`, 10/11 digits → every 4-4-2 / 5-3-2 / 5-4-1 reading in one quoted OR query), the unquoted fallback is gone, and a hit is accepted only when its `product_ndc`/`package_ndc` holds a candidate. `OpenFDAData.package_ndc` added; cache key `fda:ndc:v2`.
- **WHO statistics keep the right slice**: GHO rows carry sex and age in `DimNType`/`DimN`, not the `Sex` field the parser read, and neither path ordered its request. `get_health_statistics` kept one arbitrary row per country (often the female or male value) and labelled it "All"; `get_child_health_statistics` could return 1978 data ahead of 2023. Both now call `_fetch_latest_slices` (`$orderby=TimeDim desc`, latest year per country × Dim1-3 slice, `sex`/`age_group` read from the dimensions), with the both-sexes value first within a year. Cache keys `who:v2`, `child_health:v2`.
- **WHO statistics never cache a partial answer**: `get_health_statistics` and `get_child_health_statistics` wrote their result to the cache whenever at least one indicator answered, so one failed indicator fetch (or a failed indicator lookup that a name variation recovered) served the incomplete set for the whole 7-day WHO TTL. A result with a failed request is now returned with `error=True` and not cached, as `search_medical_databases` does. Cache keys `who:v3`, `child_health:v3`: `main` between #59 and this fix cached partial answers under `v2`.
- **Medical PubMed rows read the right year, DOI and PMCID**: `medical/pubmed.py:parse_pubmed_xml` took the first `<Year>` in the record (`DateCompleted`; PMID 31018962 read 2020, its PubDate is 2019 Aug) and the first DOI/PMC `ArticleId` anywhere, including the reference list. It now maps `PubMedProvider.parse_record` output (the core record parser, now public) to `MedicalArticle`, so `search_medical_databases`, `search_medical_journals`, the guideline/AAP tools and `search_pediatric_literature` share the core parser; Bookshelf records are kept. `MedicalArticle` gains `study_type` and `evidence_grade`. Cache keys `pubmed:search:v2`, `medical_databases:v2`, `medical_journals:v3`, `guidelines:v3`, `bright_futures:v2`, `aap_guidelines:v2`, `pediatric_journals:v3`; `pubmed:search` rows are always `{"articles", "relaxed_query"}`, so the legacy bare-list read path is gone.
- **`search_medical_databases` no longer calls every review "Cochrane" or caches a partial set**: the Europe PMC leg labelled every systematic review/meta-analysis `source_database="Cochrane"` and filled a missing journal with "Cochrane Database Syst Rev". It now keeps the real `journalTitle` and uses "Cochrane" only for a Cochrane journal, "Europe PMC" otherwise (`_search_cochrane` → `_search_systematic_reviews`; tool docstring corrected). When any leg fails, the merged result is returned with `error=True` but not cached, matching `FDAClient.search_drugs`.
- **Guideline organisations are matched as names, not substrings**: `extract_organization` ran `(World Health Organization|WHO)` and a `.*?` "American … Society" pattern with `IGNORECASE`, so "infants who present" became `who` and "Worldwide, the practices … Committee" became one organisation; the `organization` filter was a lowercase substring test, so "accuracy"/"whose" passed `ACC`/`WHO`. A small `KNOWN_ORGANIZATIONS` table now matches full names case-insensitively and acronyms only in capitals as whole tokens; other bodies match a case-sensitive capitalised-name pattern that stops before document words ("Clinical Practice Guideline"). Overlapping matches keep the longest, and every body of a joint guideline is named in order ("AHA/ACC" → "American Heart Association / American College of Cardiology"); the title outranks the abstract. `organization_matches` applies the same rules to the filter, and splits the request at `/`, `,`, `;` and parentheses, so "American Academy of Pediatrics (AAP)", "the American Heart Association" and "ACC/AHA" each stand for the table bodies they name. `GuidelinesEngine` merges one guideline published in two journals (same DOI, same `guideline_key` title without the "A Report of the …" tail, or a ≥40-character key prefixing the other; a title match needs the two years at most one apart, so a 2011 guideline and its 2019 "(Update)" stay two editions) after the organisation filter and before scoring, so the kept copy is one that passed the filter, and `search_aap_guidelines` merges with the same rule. PubMed-backed AAP rows take their category from the title marker (Clinical Practice Guideline / Clinical Report / Policy Statement / Technical Report) instead of always "Policy Statement".
- **`search_clinical_trials` takes `intervention` and `condition`**: the whole query went to `query.term`, which ClinicalTrials.gov ANDs word by word ("efficacy of metformin versus insulin in pregnant women with gestational diabetes mellitus for neonatal hypoglycemia outcomes" matched 5 trials; `query.intr=metformin`, `query.cond=gestational diabetes`, `query.term=neonatal hypoglycemia` matched 30). The optional arguments go to `query.intr` (route words such as "intravenous" and doses such as "500 mg" dropped; a number or unit word alone, as in "penicillin G" or "interleukin 2", is kept) and `query.cond`; only the query's other words, stopwords and "vs"/"versus" removed, stay in `query.term`. With an `intervention`, up to 50 studies are fetched and only those with an intervention name (or other name) that contains the drug as a whole phrase, or is itself a whole phrase inside it ("Metformin" for "metformin hydrochloride"), are kept; when none qualifies the fetched trials are kept rather than cached as an empty answer. UNKNOWN-status trials sort last before the `limit` cut. Calls without the new arguments send the same request as before. Cache key `clinical_trials:v2`.
- **BVS browser tier waits out the shield after a clean goto**: measured against live `pesquisa.bvsalud.org`, a clean `page.goto` lands on the 403 Bunny interstitial and the JSON replaces it about 12 s later, so the single read after a clean goto always classified the interstitial as a block (`brazil_guidelines` returned `backend_error`). `_camoufox_fetch` now reads for up to `_CAMOUFOX_SHIELD_CLEAR_MS` after every goto, not only an aborted one. A page that never becomes a payload still ends the tier after one budget and one navigation.
- **Duplicate-DOI papers dropped from OA annotation**: `annotate_oa_status` keyed its batch lookup maps `doi_map[doi] = paper` / `pmid_map[pmid] = paper`, so when two papers in a `search_papers` batch shared a DOI (even a case-variant) or PMID, the later paper overwrote the earlier one, which kept `oa_status="unknown"` and got no `pmcid` backfill. The maps are now identifier → list of papers, the batched query sends one clause per unique identifier, and every paper sharing a matching identifier is annotated. The skip logs count papers, not query clauses. The result loop now applies one Europe PMC row to both the DOI and the PMID bucket, so a batch holding the same work under two identifier shapes annotates both copies; papers that carry a DOI and a PMID now contribute an `EXT_ID` clause as well as a `DOI` clause, so a row that Europe PMC returns PMID-only still matches them. When Europe PMC returns several rows for one paper, the first row now wins (previously the last row's `oa_status` did). Batches of more than 50 papers are split into concurrent requests of at most 50: one query for roughly 110 papers carrying both identifiers exceeds Europe PMC's ~7.7 KB request-URL limit (HTTP 400/414) and annotated none of them, and the old `pageSize` cap of 100 silently dropped rows beyond 100. `search_papers` never passes more than 50 papers, so its request is unchanged.
- **Camoufox browser tiers survive an interstitial-aborted navigation (PR #54)**: a Cloudflare/Bunny interstitial navigates the page itself while `page.goto` is in flight, which aborts it with `NS_BINDING_ABORTED`, and `page.content()` raises while the interstitial JS is mid-redirect. The AAP guideline scrape, the BVS search tier (`BrazilMoHEngine._camoufox_fetch`) and the mirror-tier browser fallback now share `utils/browser.py` (`goto_tolerant`, `read_content_settled`). After an aborted goto, BVS keeps reading until the payload parses and the mirror tier until the Cloudflare markers are gone; a clean goto keeps the single read. Before, the AAP abort escaped ahead of its settle/re-navigate recovery (`search_aap_guidelines` returned `error=True`), an abort killed the whole BVS browser tier, and the mirror tier's per-mirror `except` skipped the mirror. The AAP scrape also polls until the challenge clears (≤20 s) instead of a 5 s `wait_for_selector` that fired mid-challenge, still waits for result items on a challenge-free page, and derives its 60 s ceiling from the phase caps.
- **WHO IRIS embedded bitstreams**: `_extract_pdf_link_from_item` read `bundle._embedded.bitstreams` as a bare list, but DSpace embeds it as a HAL page object (`{"_embedded": {"bitstreams": [...]}, "page": {...}}`), so an item fetched with `embed=bundles/bitstreams` never yielded `pdf_url`. The test fixtures now use the live shape.
- **Long `Retry-After` no longer stalls calls for minutes**: a `Retry-After` beyond `MAX_RETRY_AFTER` (60 s) used to be clamped to 60 s and retried up to three times, so an OpenAlex 429 (`Retry-After: 660`, keyless daily budget exhausted) turned the optional citation enrichment in `get_metadata` into a ~180 s stall and client-side timeouts. `AsyncHttpClient.get` now fails fast on such a response and short-circuits the host until the stated time (capped at 30 min), so callers fall through to their other sources immediately.
- **Brazilian guideline ranking — position prior scoped to BVS**: `rank_brazil_guidelines` applied the BVS Solr position prior over the merged gov.br catalog + BVS list, so the catalog row at index 0 took the top-rank bonus whatever its relevance. The prior now follows each record's rank among BVS records (`BrazilGuideline.origin`). Catalog rows score on lexical coverage.
- **Undated records take a neutral recency**: across the medical rankers, a record with no year (every PCDT catalog row) took the mean recency of the dated records in its pool instead of a 10-year default age. `CACHE_SCHEMA` v3 (`brazil_moh`, `govbr_common`) retires rows cached without `origin`.
- **`search_pediatric_drugs` admits pediatric labels only**: the filter substring-matched `"child"`, so every OTC label passed on "Keep out of reach of children", and so did adult labels mentioning "childbearing". Any boxed warning also counted. It now matches whole words after removing the OTC child-safety line, and a boxed warning counts only when it names a pediatric population. Cache key `pediatric_drugs:v2:`.
- **Journal filters survive query relaxation**: `search_medical_journals` and `search_pediatric_literature` pass their `[Journal]` clause as `MedicalPubMedClient.search_articles(filters=)`. The client ANDs it onto every relaxation rung. Composed into the query, it went through `relax_ladder`, which stripped it, so relaxed rungs searched all of PubMed. `pediatric_literature` now also ranks on the user query instead of the composed term. Cache keys `medical_journals:v2:` and `pediatric_journals:v2:` retire rows cached from unfiltered searches.
- **`search_papers` PubMed hits carry abstracts**: `PubMedProvider.search` fetches records with EFetch instead of ESummary, which has no abstract field. PubMed hits were being re-ranked on their title alone and returned with an empty abstract. Bookshelf chapters (e.g. StatPearls) are parsed too. Author names now use the `"Forename Lastname"` form that `fetch_abstract` already returned.
- **Mirror-tier Referer header**: PDF fetches now send the landing mirror page as `Referer`, which some upstream PDF hosts require. When the host refuses that header — a 401/403 or a bot-challenge page — the fetch is retried once without it, for mirrors whose hotlink protection accepts only bare requests. A request that fails outright (timeout, 5xx, transport error) is not retried and falls through to the next mirror instead (PR #25).
- **NCBI credential preservation**: `AsyncHttpClient._inject_credentials` now merges caller-provided `params` into the URL before credential injection so `httpx` does not overwrite authentication query parameters when `params` is supplied (PR #18).
- **ClinicalTrials.gov query term limit**: Capped `query.term` at 10 terms (`CT_MAX_QUERY_TERMS`) to prevent CT.gov Essie parser HTTP 400 "Too complicated query" failures on complex natural-language queries (PR #15).
- **PubMed metadata parsing DOI collision**: Fixed `PubMedProvider.fetch_abstract` to skip `ArticleId` tags nested within `ReferenceList`/`Reference` blocks, preventing cited articles' DOIs from overwriting the primary paper's DOI (PR #12).
- **openFDA natural-language drug query resolution**: Structured query ladder with quoted name clauses, per-candidate context refinement, and candidate name extraction to prevent Elasticsearch unfielded multi-term noise; bumped cache key to `fda:search:v2` (PR #11).
- **PubMed clinical guidelines over-constraining**: Added `_relaxed_queries` progressive relaxation ladder and partial publication-type score credit for keyword-layer hits to prevent empty results on specific clinical queries; bumped cache key to `guidelines:v2` (PR #11).
- **Medical PubMed relevance ranking**: `rank_medical_articles` now normalizes relevance as field coverage (title/abstract) instead of a raw weighted-hit count, so genuine lexical matches aren't outweighed by recency (PR #6, #7).
- **NCBI source-position blend**: single-source PubMed results carry a `position_weight=0.35` prior (`1/sqrt(rank+1)`) into the relevance score, keeping NCBI's own Best-Match ordering influential; multi-source merges stay at `position_weight=0.0` (PR #6, #7).
- **Rank before truncate**: `search_medical_databases` and `search_medical_journals` re-rank the deduplicated candidate pool before slicing to 20/15, instead of truncating first (PR #6, #7).
- **Journal search ranks on raw query**: `search_medical_journals` ranks against the user's original query, not the `[Journal]`-filter-expanded PubMed search term (PR #6, #7).
- Tokenizer (`_tokenize`) now guards against `None` input.
